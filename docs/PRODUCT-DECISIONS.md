# BriefDeck 产品与技术决策

记录当前产品选择及原因；功能契约见[SPEC](../SPEC.md)，测试事实见[验收记录](TEST-CASES.md)，版本和审核见[交付记录](DELIVERY.md)。本文件不重复维护版本进度和完整用量台账。

## 目标用户与产品定位

目标用户是需要将周报、项目笔记、阶段成果和截图整理为汇报材料的项目负责人及团队成员。核心价值是把已有事实转成可编辑的办公PPT，并降低用户修改一页内容和排版的成本。

当前聚焦中文16:9项目汇报，不追求完整PowerPoint编辑器，也不将卡片数量或模板数量作为设计质量指标。内容语义和重要程度决定视觉表达；没有可靠关系时保留清楚的文字。

## 技术选择及其边界

**JSON与受约束布局。** 将模型擅长的内容规划和有限设计意图交给Anna，将几何、安全回退、编辑及导出交给前端。这样能保留原生编辑、验证来源并控制成本，也意味着前端只执行已支持的组件，不是通用自由设计引擎。

**可选结构化数据。** metric/design等字段可以省略，无效字段不应破坏完整可用的正文；历史稿无需迁移。前后比较、完成量/总量和目标差距依赖明确来源及方向，不从任意两个数字强行画图。来源编辑后无法可靠同步的指标必须失效，而不是继续显示旧计算。

**共享排版与原生导出。** PptxGenJS输出文本、形状和图片，避免把整页截图当成最终PPT。浏览器与导出共享几何，仍须检查字体和Office差异；原生对象可编辑不等于所有环境逐像素一致。

**小前端与宿主能力。** 原生ES Modules组织编辑器；PDF.js、JSZip处理资料；Anna Runtime承担模型调用和账号内存储。应用不另建模型服务，不要求用户提供第三方模型密钥。原始表单资料不作为历史稿内容保存，保存的是文稿、风格和画布图片及必要回执。

**控制失败成本。** 先本地校验输入，主要回归使用mock；真实测试用于检查模型是否采用设计和实际视觉质量。模型处理后即使返回无效JSON/设计，也可能已计费，应用无法承诺失败退款。thinking:false只是请求偏好；有效输出预算仍受平台/模型限制。

## 用户修改与恢复原则

1. 用户内容优先。原文、数值、口径和限制不得因模板容量或视觉差异被删改；无法排下时保护旧稿并说明。
2. 布局与内容分开。P2/P2.5撤销只恢复视觉，不撤销用户文字或图片编辑，也不能恢复过期指标。
3. 当前页隔离。候选确认前原稿不变；取消、切页、改稿或风格变化后，迟到结果不能覆盖其他页。
4. 成本可知。用户事先知道操作可能多次计费，结束后看到本次累计积分；不在普通界面暴露网格错误、模型或token细节。
5. 失败可追查。保留真实返回、实际校验错误和逐次用量，诊断默认隐藏；失败、取消和过期分别记录。

## SDD协作与验收方法

采用轻量SDD：先确定用户场景、输入/输出、边界和异常，再对齐验收编号，增量实现，先mock回归，最后有限真实测试。SPEC维护当前有效契约，TEST-CASES保留每次失败和复测，DELIVERY维护版本、平台状态与用量。

- 产品负责人负责产品范围、取舍、真实操作及视觉验收，提出问题并确认效果。
- Codex协助代码实现、自动化测试、诊断和文档；不替用户虚构线上操作或验收结果。
- Anna在产品运行时生成汇报内容与单页设计JSON；它不是本项目源码开发过程的替代描述。

生成成功、组件实际采用、内容/视觉质量合格、PPTX可编辑、跨账号可用是分别验证的结论。每个spec点应关联自动化或人工用例；未执行项保持待验证，不能以“有测试文件”推断已完成真实验收。

## 设计演进

| 演进依据 | 当前决定 | 验证记录 |
| --- | --- | --- |
| 六页原型和等权卡片使生成稿像换字模板 | 改为4–12页、结论型内容规划、主证据及明确数据/角色/顺序关系；能力仍受组件约束。 | TEST-CASES M2.4、P1、V1、V2 |
| 四阶段被固定1–3条校验拒绝 | 内容条数与布局能力解耦，实际密度适配；完整保留全部要点。 | D1失败与复测 |
| focus只有深色块、重要数字不突出 | 使用可追溯结构化指标；重点既需语义依据，也需实际空间兼容。 | P1.1、P1.2、V1 |
| 单页模型返回非法网格/不兼容组合 | 请求候选由同一校验器预筛；最多4次受控纠错，继续严格校验，失败原稿不变。 | P2.5真实失败及纠错mock回归 |
| 模型强制推理导致预算被占用 | 移除模型偏好，按页数预留预算，明确截断才受控重试；不绕过硬限制。 | G1 |
| 上传测试版被误认为已经正式交付 | 明确开发测试、审核、发布与跨账号验证四个阶段，平台审批阻碍如实记录。 | R1及DELIVERY |

## 暂缓能力

M7“分挡生成PPT”仅预留，未实现；AI生图、扫描PDF OCR、任意自由网格/通用图表引擎、多人实时协作和完整PowerPoint编辑能力均不在本轮交付范围。当前版本保持功能冻结，后续改动按需求、规约和验收编号推进。
