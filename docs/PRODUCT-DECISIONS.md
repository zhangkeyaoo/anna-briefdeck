# BriefDeck 产品与技术决策

BriefDeck 帮助项目负责人和团队成员把已有资料整理成可编辑的项目汇报 PPT。典型场景是把周报、会议笔记和监控截图整理为例会材料，核对关键数字、风险和待决策事项，再交给同事继续编辑。[功能规格](../SPEC.md) · [验收记录](TEST-CASES.md)

## 产品范围

| 能力 | 产品决定 | 规格 |
| --- | --- | --- |
| 混合资料 | 笔记、Word、TXT、带文字层的PDF及PNG/JPEG截图，可混合或只用文件。 | M1、M8 |
| 生成设置 | 默认6页、可选4–12页，汇报对象、简约/科技风、自选主色及制作要求。 | M1、M2 |
| 逐页设计与编辑 | 模型选择叙事及有限构图，画布编辑文字，多图可拖动、缩放和删除，PPTX原生可编辑。 | M3–M5、P1 |
| 我的PPT | 生成稿自动保存，统一保存入口，支持新建、切换、恢复及逐稿删除。 | M6 |
| 本地更换布局 | 指标页、总结页选择2–3种兼容布局，保留内容及原始设计，可撤销/恢复，不调用Anna。 | P2 |
| 分挡生成 | 挡位与成本取舍待定义；按需AI配图已移出当前排期。 | M7预留 |

4 页适合简报，6 页适合常规周报，12 页留给资料充足的阶段汇报。页数上限同时控制单次请求的输出长度。资料不足时，生成稿用「待补充」标记缺失事实。

实现与验证结果见验收记录；R1的测试版本、审核及公开访问状态由交付记录集中维护。[交付记录](DELIVERY.md)

## 用户流程

1. **准备资料。** 选择文件或粘贴笔记。文件列表默认收起。展开可看读取状态、提取文字和图片缩略图。出现文件错误时自动展开，可移除单项后继续。
2. **设定并生成。** 选择页数和风格，按需填写汇报对象、主色和制作要求。制作要求可指定重点、语气或结构。每次有效生成提交一次 Anna 请求，收到结果后校验页数、文案和设计。涉及截图时提醒用户核对识别出的数字。
3. **在画布上编辑。** 点击标题或要点可修改文字。插入的图片是独立对象，可批量加入、拖动、等比缩放和删除。指标对比条从要点中的数值派生，编辑相关数值时同步变化。
4. **保存或下载。** 成功生成会打开新稿并加入历史，旧稿可继续打开。标准 16:9 PPTX 保留 PowerPoint 原生文字、形状与独立图片。浏览器预览与导出共用排版数据。

## 为什么让 Anna 逐页设计

`0.1.3` 的正文页由语义标签映射到固定布局。真实复核发现，生成稿与示例使用相同案例，标题和文案虽有变化，页面骨架仍很相似。自选主色多用于线条和标记，背景以及大色块仍维持原主题色。

M5 把「这页讲什么」与「这页怎么排」拆开。Anna 在一次回复中返回正文、页序和逐页设计，用紧凑的网格参数选择文字、重点、时间线阶段或同单位数值对比。浏览器检查区域越界和重叠，设计无效时保留该页可用文案并回退至默认布局。这样既能按内容选择构图，也能继续原生编辑。暖金等自选主色会影响封面、背景和主要卡片，正文保留可读的对比色。

验收用两份不同结构的资料。客服试点用对比条呈现响应时间，档案迁移用时间线呈现阶段顺序。两套稿件以模拟结果验证布局差异和 PowerPoint 原生对象。[M5 详细规格](../SPEC.md#m5-anna-逐页设计) · [M5 验收](TEST-CASES.md#m5-逐页设计)

P1 进一步让模型按听众组织整份汇报。指标页可由模型指定一个直接支持结论的主证据，应用给它更大的面积和字号，辅证保留上下文。没有明确主次时可继续并列。优先在生成时减少重复文字，渲染只精简可以确定的复述。兼容之前的稿件和回退策略。[P1 验收](TEST-CASES.md#p1-内容质量与专业视觉)

P1.1 以真实响应补上设计意图的映射。没有 lead 的指标页可使用唯一 focus 指定主证据，已有 compare 和 milestone 的构图优先保留。决策页可明确指定建议，也兼容唯一标为「当前建议：」的要点。复合指标的原文和口径保持完整。未来若要把同一要点中的多项数值分别展示，需由模型显式提供标签、数值、单位及来源要点，而后校验引用。封面数组契约和未经证实因果的限制已写入提示词，校验失败可直接下载本次原始输出作诊断。[真实响应回放验收](TEST-CASES.md#p11-真实生成质量修复)

## 我的 PPT 与保存范围

顶部「我的 PPT」显示文稿名、页数和最近编辑时间，并标记当前稿。示例默认供试用，需要保留时点「保存当前 PPT」。生成稿自动保存，手动再次保存会更新同一条记录。

「新建空白」清空当前画布和输入，历史仍可打开。删除需要确认。删除当前稿会关闭画布，输入资料仍保留。保存和删除失败时提示原因或后续操作，当前窗口的稿件仍可下载。

Anna 内的稿件使用当前账号和应用自己的存储空间，本地预览使用浏览器 IndexedDB。保存的是稿件文字、版式、风格、主色和画布插图。生成前的原始笔记和资料附件不进入历史。[M6 详细规格](../SPEC.md#m6-我的-ppt) · [M6 验收](TEST-CASES.md#m6-我的-ppt)

## 资料提取与额度

- Word、TXT 和 PDF 先在浏览器提取文字。PDF 按页预览，混有无文字页时跳过这些页并提示。纯扫描件需要先做文字识别。复杂多栏文档的行序应在预览中核对。原 PDF 留在浏览器，生成请求只携带提取文字。
- PDF 与 Word、TXT 共用最多两份文档的限制。每份 PDF 最多 5 MB、50 页。笔记和提取文字合计最多 6,000 字。作为模型资料的图片最多两张。画布插图与模型资料各有独立流程。
- 图片资料经浏览器校验和压缩后，与文本一起交给支持视觉的模型。预读、载入示例、编辑、历史操作和本地导出均不触发模型调用。真实生成失败后由用户决定是否重试。
- 记录 Anna 返回的模型、CU、输入与输出 tokens、推理 tokens 及有效上限。字段缺失时保留未知状态。真实用量按宿主回执登记，调用上限不能作为费用承诺。

## 产品区分度与验收方法

产品围绕已有项目证据展开。用户先能看见资料被读出了什么，再检查生成稿有没有保留关键事实，最后可以在 PPTX 里继续修改。真实验收样例把处理量与待决策事项放在 Word、响应时间放在监控截图，以便核对两种输入分别有没有进入汇报。关键数字的来源标注可作为后续候选。

| 阶段 | 用户参与 | Codex 交付 |
| --- | --- | --- |
| 确定范围 | 确认目标用户、文件格式、页数、图片用途和典型资料 | 记录选择、边界与备选方案 |
| 锁定规格 | 核对样例中应保留的数字、风险与决策 | 在统一规格中写出可复现的验收条件 |
| 实现与复核 | 根据真实使用反馈指出不清楚的界面和不适合的成稿 | 用模拟宿主验证流程，保留缺陷和复测证据 |
| 平台交付 | 验收安装、使用和实际生成效果 | 记录测试版本、用量、审核和公开状态 |

## P1.2 指标泛化

本轮采用最小句式兼容修复，继续要求 Anna 选择主证据，不根据数字大小猜测。原生大数字支持单一指标和明确同单位前后比较，增加“缩短至/缩短到”。多组比较或复合完成量不确定时保留文本，完成量、总量和完成率不拆散、不补算。Prompt 要求主指标单独成点，其他口径另列。

历史存储 snapshotDraft 完整复制页面，restoreDraft 直接恢复，已有 lead、design、layout 和原文，不新增存储。PPTX 不含原始 JSON；迁移原响应未保存，因此只验证真实内容摘录加明确模拟的参数，不能声称恢复了真实设计意图。本轮结束 P1，转入 P2。


## P2 降低修改成本

用户可对当前指标页或总结页选择兼容布局，无需重新生成整份PPT。优先复用既有主证据、并列卡片和简洁行式组件；没有可靠主证据时不提供重点指标，不自动选择第一个或最大的数字。突出首条是用户显式选择，只作用于当前页。其他页型暂缓，避免扩大成完整编辑器。

manualLayout仅记录用户的呈现选择，原layout语义、design、composition、lead和全文保留。未知值忽略并回到既有布局；撤销/恢复只改呈现，不回滚文字或图片。已有存储直接保存该字段，预览和PPTX共用排版。本轮无Anna新增调用。

文档统一为README、SPEC、产品决策、测试验收、交付运维五份。后续功能按原有编号扩展，固定输入和失败截图归入验收，历史提示词与计费说明归入交付，避免继续新增阶段文件。
