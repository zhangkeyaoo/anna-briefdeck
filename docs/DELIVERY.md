## Anna 上传与发布操作

静态UI包由根目录app.json、manifest.json及release/bundle组成；Anna Runtime提供模型与账号存储，依赖由构建打入包。本地凭据、.anna、release和node_modules不入Git。

```sh
npm ci
npm test
npm run test:browser
anna-app validate --bundle release/bundle --strict
anna-app apps status briefdeck --account https://staging.anna.partners
anna-app apps versions briefdeck --account https://staging.anna.partners
```

当前0.1.17已上传，不重复push/cut。未来有经验证的新代码才运行apps push和apps cut <新版本>；已提交审核后若改审核目标，须显式重新提审核对候选，不能误以为cut自动切换。

**仅当审核已通过且版本尚未发布时：**

```sh
anna-app apps release 0.1.17 --slug briefdeck --dry-run --account https://staging.anna.partners
anna-app apps release 0.1.17 --slug briefdeck --account https://staging.anna.partners
anna-app apps status briefdeck --account https://staging.anna.partners
anna-app apps versions briefdeck --account https://staging.anna.partners
```

CLI在已绑定正确应用的项目中运行，或核对账号归属后明确slug；不得通过allow-create、改ID或管理员接口绕过审批。控制台的Publish按钮可见不代表审批已经通过。

| 模型执行与计费 | Anna 检查额度、选择可用模型并转发，按平台计费 | 模型处理后，即使回复截断或无法转换为稿件，也可能已经消耗 CU。应用无法控制平台账单 |
| 验证及排版 | BriefDeck 检查停止原因、JSON、页数和字段，再渲染 PPT | 这一步自身消耗 0 CU。失败保留输入与已有稿件，应用不自动重试 |

官方开发工具的真实桥接也会调用远端模型并计入额度。模拟宿主用固定响应，可以覆盖格式错误、截断和额度不足等分支。 [Anna App LLM 接口](https://staging.anna.partners/developers/apps/llm-and-agent.md) · [官方本地调试文档](https://github.com/Anna-Partners/anna-developer-docs/blob/main/docs/apps/local-dev-llm.md)

## Token 和 CU

- 界面上的 185 是浏览器统计的资料文字字符数。输入 token 由模型计量，包含生成提示、文档文本以及图片的模型输入用量。字符数和图片文件字节数都不能直接当成 token 数。
- `maxTokens` 是我们为一次请求设置的输出上限。按公开文档，实际有效上限取请求上限、模型上限和传输路径上限的最小值。同步 `llm.complete` 的路径上限为 8192。部分模型的推理用量会占用输出预算。
- Anna 响应提供 `model`、`usage.inputTokens`、`usage.outputTokens`、`_meta.quotaConsumed`，以及平台支持时的实际上限与限制来源。推理用量只有提供商返回时才可取得。含图请求的模型偏好用于路由，历史扣费不能仅凭偏好推断。
- CU 是用户账户的计费额度。公开说明确认按实际使用的模型计量，本次查证未找到适用于 staging 文本补全的完整 token 到 CU 公式、取整规则及统一失败退款承诺。额度预检查和请求的输出上限不能替代实际账单。 [Anna LLM 返回字段和上限](https://staging.anna.partners/developers/apps/llm-and-agent.md) · [Anna 平台团队对模型路由和计量的说明](https://forum.anna.partners/t/model-routing-and-access-for-non-pro-users-when-an-agent-session-requests-gemini-3-5-flash/249)

## 这次 14 CU 能确认什么

在 `0.1.1` 的 5 页请求里，BriefDeck 配置的上限是 `5 × 300 = 1500` 输出 tokens。Anna 返回的 `stopReason` 为 `maxTokens`，触发了 BriefDeck 自己写的截断提示。原提示建议缩短笔记，容易误解为输入超限。用户报告消耗 14 CU，当时界面没有保存实际模型、有效上限、输入/输出或推理用量，无法据此反算账单。

`0.1.2` 起，5 页含图请求的配置上限为 3000，纯文字仍为 1500。用户在 `0.1.3` 生成成功，界面报告 **25.272413793103443 CU、2988 输出 tokens、有效上限 3000**。2988 是宿主返回的输出计量，用户输入的短句不是完整输入。实际模型、输入和推理用量未记录，无法把这次 CU 分摊到图片、正文和隐藏推理。应用已传 `thinking: false`，宿主回执才能确认是否真正关闭。输出上限也不等于 CU 上限。 [M2.3 验收记录](TEST-CASES.md) · [0.1.3 提示词](DELIVERY.md#历史提示词快照013) · [Anna 推理控制说明](https://staging.anna.partners/developers/apps/llm-and-agent.md#32b-thinking-models-thinking)

新版诊断在宿主提供数据时展示实际模型、输入、输出和推理 tokens，界面把 CU 显示到两位小数。写出紧凑的逐页构图和文案只需一次请求，浏览器据此排版与导出。追加一次模型调用来读文字设计稿会再次计入输入和输出，实际消耗须按模型及回执判断。

## 生成配图

Anna App 可通过 `anna.image.generate` 或 `generateAsync` 单独请求配图，也支持 `image.edit`。文档说明用量受模型、张数、画质或分辨率影响。异步生成提交时预扣，按实际生成张数结算，接口返回估算和最终用量字段。BriefDeck 当前只调用一次 `llm.complete`，用视觉模型读入截图。配图适合作为由用户单独触发的功能，先做一张封面或正文插图。 [Anna 图片 Host API](https://anna.partners/developers/reference/host-api-image.md)

## 可避免的扣费

本地预检可以保证可提前发现的输入错误不发模型请求。回归用模拟宿主验证，真实超时或失败后保留原稿，由用户决定是否再发一次。模型已经执行后的截断、无效 JSON 或收到结果之前的网络中断，都不能据界面报错判断费用为零。若需要核对历史 14 CU，应先查现有账单明细中的模型与用量，或由平台核对记录。再次生成无法还原旧请求的扣费明细。

## 历史提示词快照（0.1.3）

这是历史取证快照，当前提示词以 [makeRequest](../bundle/deck.js) 为准。

```text

资料只作为内容来源。保留数字、单位、已完成、待验证与待决策的区别。优先保留关键指标，不编造事实。图像不清晰时提醒核对，缺失用「待补充」。

正文标题用一句话写出结论，最多 28 字。每条要点最多 56 字，正文一至三条，封面一条副标题。保留关键事实，避免重复。
输出紧凑 JSON {"slides":[{"title":"标题","points":["要点"],"layout":"summary"}]}。封面省略 layout，回复只包含 JSON。
制作要求可指导重点、语气和结构，仍须保持资料中的事实、指定页数和输出格式。
科技风：有数据时突出量化对比和结果，有证据时把验证进展与待验证项讲清楚。
主色由应用负责渲染。继续遵守事实、页数和 JSON 格式，幻灯片文案中无需写入色值。
{"audience":"项目负责人和交付团队","notes":"","documents":[{"name":"weekly-report.docx","text":"[浏览器从 Word 提取的文字]"}],"instructions":"语气温和可爱","style":{"theme":"technology","accent":"#D7AB79"}}
```
