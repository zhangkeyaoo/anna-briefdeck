# BriefDeck 下一轮规格

## P1.2 指标泛化（本轮收尾）

输入为既有页面数据，继续使用可选 lead 或唯一 focus。主证据缺失、无效或包含多个比较关系时保留原布局/文字，不推断业务重点。

- **P1G.1** 单一指标可突出数值；明确的同单位前后比较支持“缩短至/缩短到”，与旧的“降至”和箭头共用排版及变化率计算。零基线、负值和方向矛盾不计算变化率。
- **P1G.2** 迁移摘录在模拟 lead 和唯一 focus 下显示 8→2 分钟、约75%，保留12,000份、9,600份、80%、99.2%/99.5%及36人。多个比较不得擅自选第一组。完成/总量关系只保留原文，本轮不新增结构化协议或自动比例推断。
- **P1G.3** Prompt 要求主指标单独组织并由 lead 指定，其他口径另列。保留完成量/总量与限定条件，不增加调用或输出预算。Prompt 的真实遵循尚未重测。
- **P1G.4** 完整客服响应与迁移真实内容摘录分别回归；迁移设计参数明确标为模拟。历史快照/恢复保留 lead、design，浏览器和可编辑 PPTX 共享排版，无效参数安全回退。

本轮完成后停止扩展 P1，进入 P2；P2 的具体内容按后续产品优先级确定。

## P1 内容质量与专业视觉

在一次原有 Anna 请求内，先按听众组织整份汇报，再输出各页结论及证据。标题用资料可支持的判断。重点明确时可在指标页加 `lead`，值为从 0 开始的要点索引。前端给其更大的区域和字号，辅助指标以较紧凑的组呈现。有效 `lead` 优先于指标页的构图参数，非指标页、缺失、越界或非整数值沿用原布局。历史稿无需迁移。画布编辑保持要点索引和底层原文。

去重限于重复呈现的数字和明确的标签句。统计周期、范围、口径、限制及不确定性必须保留。相对变化只从同单位、非零可比较基线计算。当前方案继续共用浏览器与 PPTX 排版数据，不增加模型请求。

- **P1.1** 请求检查负责人和执行团队的不同规划要求，保留单次调用和现有输出预算。真实验收检查一次负责人生成的页序、标题和事实。
- **P1.2** 指定不同的主证据，核对视觉重点随之变化。缺失或无效的索引、非指标页及旧稿保持现有布局。
- **P1.3** 在预览和 PPTX 检查重复值已精简，范围和限定条件保留。编辑后保留完整原句并重新计算对比值。零基线不显示百分比。
- **P1.4** 检查窄窗口、长文本、形状边界与原生 PowerPoint 导出。真实生成后回看是否需要收尾调整。

### P1.1 真实响应修复验收

2026-11-20 以用户提供的六页真实 JSON 作为主要回归输入。

- **P1R.1** metrics 中唯一 focus 在缺少 lead 且没有 compare 或 milestone 时进入主证据布局。有效 lead 优先，已有 compare 或 milestone 设计保留。单条复合指标中的限定、目标、工作量和复核文本完整保留。无法严格读取比较关系时保留文本。
- **P1R.2** decision 支持有效 lead 和唯一显式「当前建议：」标记。建议使用更大的区域和字号，条件在辅助区；缺少明确标记及 lead 时沿用已有布局。编辑始终使用原始要点。
- **P1R.3** 提示词明确封面 points 恰好一个字符串、正文 1–3 个字符串，加入未证实因果约束。保留原有页数、文案长度、设计参数校验。结构校验失败时可查看和下载本次模型原始输出、错误与用量，旧稿仍在。
- **P1R.4** 六页真实响应在浏览器宽窄窗口无溢出，导出为原生文字和形状。因果约束以提示词契约检查，回放不改写旧模型输出。保留 1800 token 上限，回放与诊断下载不增加模型请求。

## M5 Anna 逐页设计

**场景。** 用户希望同一类内容也能根据讲述目标使用不同布局。客服试点适合强调响应变化和扩容决策，迁移计划适合强调阶段和依赖关系。

**输入。** M1 校验通过的资料、听众、页数、风格、主色及可选制作要求。沿用既有长度和页数边界。

**正常输出。** 一次 Anna 文字请求返回紧凑的逐页设计与最终文案。Anna 决定叙事次序、每页重点、元素组合和相对大小或位置。初期覆盖指标对比、时间线和重点结论。浏览器校验设计，驱动预览并导出原生 PPTX 文字与形状。使用同一个主色派生封面及正文大色块，保持文本可读。

**边界。** 先用现有卡片、纵排和重点构图作为回退。新设计使用有限的原生元素及布局参数，控制每页对象数与响应长度。不执行模型返回的代码。排版、预览、编辑、导出均为本地操作。

**异常输出。** 单页设计参数非法时优先保留该页可用文案，用默认布局显示。整份文案、页数或格式无效时保留原稿并提示。记录宿主实际提供的模型、CU、输入、输出、推理用量和有效上限，缺失字段按未知记录。

**结构化设计。** 正文页可返回 `design`。每个元素为 `[要点序号, 元素, x, y, 宽, 高]`，坐标在 12×12 正文网格内。序号从 0 开始，每条要点恰好对应一个元素。元素间不能重叠。封面沿用现有可编辑标题和副标题。省略 `design` 时继续兼容原来的 `composition` 和 `layout`。

| 元素 | 最小宽×高 | 输出 |
| --- | --- | --- |
| `text` | 4×5 | 原生文本框与卡片 |
| `focus` | 4×5 | 强调色块与可编辑重点文案 |
| `milestone` | 4×6 | 带阶段编号的原生时间线块，日期保留在文案中 |
| `compare` | 6×7 | 从同单位的前后数值派生原生对比条。读不到可绘制数值时保留正文，编辑正文时同步重新计算 |

| 规格 | 验收用例 | 状态 |
| --- | --- | --- |

## M6 我的 PPT

**场景、输入与输出。** 用户从顶栏「我的 PPT」新建或打开稿件。下拉箭头与按钮文字垂直居中。生成成功即新增一份并自动保存，切换时恢复该稿的文字、图片位置、主题及主色。「保存当前 PPT」用于保存当前画布里的任意稿件，已保存的稿件原地更新。菜单显示未保存、正在保存、已保存或保存失败。「新建空白」清空当前画布与输入，已保存稿件继续可打开。列表每份稿有「删除」入口，经确认后从历史移除。若删除的是当前稿，同时关闭画布，保留当前输入资料。

**边界与异常。** Anna 中使用当前账号和 App 自有的 Anna Persistent Storage。本地预览使用当前浏览器的 IndexedDB。稿件保存画布、版式、风格、主色和插入的图片，输入表单与原始资料独立于稿件。受宿主或浏览器存储配额影响，保存失败时提示并保留当前会话内的稿件和下载能力。删除取消或失败时保留稿件，确认成功后无法撤销。生成失败保留已有稿件。Anna 写入和删除带版本匹配，遇到其他窗口的更新冲突时保留本窗口数据和下载能力。

- **M6.1** 连续生成 4 页和 6 页两份稿，各自编辑文字、风格、主色和图片位置。来回切换和刷新后恢复旧稿，检查页数、编辑和导出对象与所选稿一致。
- **M6.2** 核对箭头对齐。示例和生成稿均用「保存当前 PPT」，生成后显示已保存，再手动保存不会重复创建。模拟存储失败，检查状态及下载能力。上述操作发起 0 次模型请求。
- **M6.3** 删除前可取消。存储拒绝删除时保留稿件。确认删除当前稿后，画布关闭，其余历史不受影响，刷新后被删稿仍不在列表。Anna 模拟及浏览器本地各验证一遍，操作发起 0 次模型请求。

## M8 PDF 资料

**场景、输入与输出。** 用户上传带文字层的 PDF，浏览器先提取并预览页内文字，再沿用 M1 的资料校验与生成入口。

**边界与异常。** 每个 PDF 最多 5 MB、50 页，和 DOCX、TXT 共用最多 2 份文档的限制。提取文本计入合计 6,000 字上限。按页处理，保留能提取文字的页。完全无文字的扫描件、加密文件、损坏文件和超限各自提示。复杂多栏与阅读顺序需人工复核。

**实施顺序。** 用两页中文 PDF、扫描件和加密样例检验浏览器端解析。正常文件的提取文字复用现有生成入口。分别核对 PDF 加 Word 或 TXT，再附一张图片的场景仍只发起一次生成请求。原始 PDF 保留在浏览器。

- **M8.1** 检查多页中文 PDF 的阅读顺序、预览、删除和同批加入其他资料。
- **M8.2** 用扫描件、加密、损坏及超限样例检查失败提示及拦截，异常文件发起 0 次模型请求。
